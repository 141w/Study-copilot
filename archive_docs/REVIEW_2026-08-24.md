## 1. 两个生产级 Bug（本轮核心发现）

### BUG-1：Embedding 模型加载无限挂起 → commit `3016672`

- **症状**：上传文档后异步任务永远卡 `running`，前端假进度条
- **根因（两层）**：
  1. `.env` 配置 `BAAI/bge-m3`，但该模型从未成功下载（HF 缓存只有 text2vec 与 cross-encoder）
  2. 更深层：即使模型已完整缓存，`huggingface_hub` 默认仍发联网版本校验请求；本机 VPN/代理环境下该请求无超时挂起 → 缓存形同虚设
- **修复**（`backend/app/core/embedder.py`）：缓存优先——先 `local_files_only=True` 纯离线加载，失败再回退在线下载
- **配套**：`.env` embedding 模型切回已缓存的 `text2vec-base-chinese/768`
  - ⚠️ `.env` 在 .gitignore 中，此改动**不入库**，换机部署需手动同步
  - ⚠️ 旧 bge-m3(1024 维) 向量索引检索会维度失配，受影响文档需重新上传

**Review 重点**：`embedder.py` model property 的 try/except 粒度——任何缓存加载失败都会回退在线（含缓存损坏场景）；若显式设了 `HF_HUB_OFFLINE=1` 则跳过回退直接走在线分支（此时 hf_hub 自身会强制离线，语义等价）。

### BUG-2：笔记语义搜索从未生效 → commit `b8cba88`

- **症状**：`POST /api/notes/search` 永远返回空列表
- **根因**：`create/update/delete_note` 从不写向量库。"端点在、服务在读，唯独没有写入方"——文档宣称的自动入索引从未实现（findings #29 只修了一半）
- **修复**（`note_service.py` +92）：
  - `reindex_user_notes()`：CRUD 后全量重建用户 `notes_{uid}` FAISS 索引
  - 选全量重建而非增量 upsert 的理由：笔记量级小 + embedder 文本哈希缓存使重复编码近乎免费 + 天然覆盖删除
  - chunk 携带 `document_id=note.id`，与搜索侧回表精确对齐
  - `_safe_reindex`：索引失败仅告警，不阻断 CRUD

**Review 重点**：
- 切片窗口 800 字符 / 步长 650（重叠 150）的合理性
- `_safe_reindex` 吞异常 → 搜索可能静默过期（下次 CRUD 自愈），是否可接受
- `tests/test_note_indexing.py` 用 fake store 隔离 embedding 的手法
