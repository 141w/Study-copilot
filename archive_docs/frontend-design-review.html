一、执行摘要

项目已完成 Element Plus 组件迁移与 CSS 变量设计系统的初步搭建，但“定义了系统，却未在组件中使用”是当前最大矛盾。大量视图仍使用硬编码色值、Tailwind 任意值、重复布局模式；暗色模式存在真实 Bug；部分视图存在功能级缺陷（如课程删除确认按钮绑定错误）。

最高优先级修复清单

  2. 修复 CourseListView.vue:119 删除确认按钮误绑定 confirmDelete 而非 doDelete。

二、设计系统审查

设计 token 集中在 frontend/src/styles/variables.css、element-plus-theme.css、tailwind.config.js 三处，但组件层并未消费这些 token，导致系统与实际 UI 脱节。

暗色模式在 Tailwind 层未启用 class 策略

Critical

tailwind.config.js 未设置 darkMode: 'class'，默认使用 prefers-color-scheme 媒体查询。而主题 store 通过 document.documentElement.classList.add('dark') 切换类名。

后果：用户在 OS 浅色模式下强制开启应用暗色模式，HomeView 等使用 dark:bg-[...] 的位置仍会显示浅色背景。

// tailwind.config.js 当前
export default {
  content: ['./index.html', './src/**/*.{vue,js,ts,jsx,tsx}'],
  theme: { extend: { borderRadius: { ... } } },
}

// 应改为
export default {
  darkMode: 'class',
  content: ['./index.html', './src/**/*.{vue,js,ts,jsx,tsx}'],
  theme: { extend: { borderRadius: { ... } } },
}

设计 token 定义了但未被消费

High

grep 全量 Vue 文件显示以下 token 零引用：

  • var(--spacing-*)：组件全部使用 mb-4、px-2 等 Tailwind 间距
  • var(--radius-*)：组件使用 rounded-xl，而 scoped CSS 写死 8px、4px
  • var(--shadow-*)、var(--transition-*)、var(--font-size-*)、var(--gradient-*)

结果：设计系统成了“文档式系统”，任何全局调整需要逐个文件修改。

品牌渐变与关键色值硬编码

High

品牌渐变 #ef2cc1 → #fc4c02 已在 variables.css:45 声明为 --gradient-brand，但 6 处以上直接写死 hex：

AppHeader.vue:15
LoginView.vue:5
RegisterView.vue:5
ChatView.vue:79 / :103 / :441
AnalysisView.vue:116

此外，近黑色 #010120 在 AnalysisView、DocumentView、UploadView、TransformDialog、ChatView 等 10 余处用于 active/hover/ring，暗色模式下几乎不可见。

Element Plus 主题与 variables.css 重复且可能漂移

Medium

variables.css 与 element-plus-theme.css 维护了两份相同语义的颜色值（primary/success/warning/danger/info/text/border）。例如：

/* variables.css */
--color-info: #3b82f6;

/* element-plus-theme.css */
--el-color-info: #3b82f6;

建议：在 element-plus-theme.css 中全部使用 var(--color-primary) 等应用 token，实现单一数据源。

卡片实现存在两套机制

Medium

22 处使用 class="el-card ..."（div + CSS 别名），3 处使用真正的 <el-card> 组件。CSS 别名在 global.css 中强制 padding: var(--spacing-lg)，导致 DocumentView.vue:40 不得不使用全项目唯一的 !p-0 覆盖。

建议：移除 .el-card 别名，全部改用 <el-card>，通过 Element Plus 的 CSS 变量统一控制。

Tailwind 默认色板泄漏

Medium

bg-blue-50、divide-gray-100、text-blue-600、text-indigo-500 等 Tailwind 默认色在暗色模式下无对应变体，会出现浅色条带/分隔线。

半径、过渡、布局数字多处重复定义

Low
  • tailwind.config.js 与 variables.css 同时定义半径 scale（6/10/14/18/24/32px）
  • Header 高度 64px、侧边栏宽度 256px 在 App.vue、AppHeader.vue、AppSidebar.vue 中硬编码耦合
  • 页面过渡 0.2s ease、侧边栏 duration-300 未使用 --transition-* token

三、架构与工程审查

TypeScript 迁移进度严重滞后

High

stores、types、services、composables、router 已全面 TS 化；但 13 个视图中仅 LoginView.vue 使用 lang="ts"，其余 12 个视图均为纯 JS，与 CLAUDE.md 中“views 渐进覆盖 TypeScript”的表述直接矛盾。这导致：

  • props 使用对象写法而非 defineProps<{...}>()
  • API 响应数据无类型，error.response?.data?.detail 等访问不一致
  • 模板中无法获得类型提示与重构支持

配置文件名与 tsconfig.node.json 不匹配

Low

实际文件为 vite.config.js / vitest.config.js，而 tsconfig.node.json 仍引用 vite.config.ts / vitest.config.ts，属陈旧引用，建议同步更新。

Element Plus 重复全局导入

Low

main.ts 已全局注册 ElementPlus，同时 unplugin-vue-components 也自动导入组件。全局注册会引入完整 bundle，建议仅保留自动导入以减少体积。

store 间存在循环/横向耦合

Medium

config.ts 导入 useChatStore 同步 LLM 设置；auth.ts 直接导入 router。建议通过组件层或事件总线解耦，避免 store 之间形成隐式依赖网。

工具函数重复定义

Medium

formatDate 在 HomeView.vue、ChatHistoryPanel.vue、NoteCard.vue 中重复实现；空状态图标容器、页面标题布局、删除确认弹窗等模式在多个视图中复制粘贴。

四、组件审查

NoteEditor 工具栏/Tab 快捷键全部失效

Critical

NoteEditor.vue:178 访问 textareaEl.value?.textareaEl，但 Element Plus el-input（textarea 模式）暴露的原生元素属性是 .textarea，不是 .textareaEl。导致 Bold/Italic/Heading/List/Quote/Code 按钮和 Tab 缩进全部在 guard 处提前返回，功能完全失效。

// 当前（错误）
const textarea = textareaEl.value?.textareaEl

// 应改为
const textarea = textareaEl.value?.textarea

ChatInput 未声明 placeholder，传入属性被丢弃

High

ChatView.vue 向 ChatInput 传入了 placeholder="输入问题，按 Enter 发送..."，但 ChatInput.vue 只声明了 loading 与 disabled props。该属性 fallthrough 到根 <div> 上并被丢弃，输入框始终显示硬编码的 输入您的问题...。

NoteEditor 预览区存在 XSS 风险

Critical

NoteEditor.vue 使用手写的正则渲染 renderedContent，并通过 v-html 输出到 DOM。内容未做 HTML 转义，恶意笔记（如 <img src=x onerror=...>）会原样执行。项目已有 composables/useMarkdown.ts 提供安全的 Markdown 渲染，应直接复用。

中文 IME 输入法未做组合保护

High

ChatInput.vue 的 @keydown.enter="sendMessage" 与 NoteEditor.vue 的 @keydown.enter.prevent="addTag" 未检查 event.isComposing。在中文输入过程中按 Enter 选词会直接触发发送/添加标签，严重干扰中文用户。

TaskPanel 状态处理与类型模型不一致

Medium

TaskPanel.vue 将 'cancelled' 作为一等状态处理，但 types/models.ts 中 Task.status 仅允许 'pending' | 'running' | 'completed' | 'failed'。UI 与类型契约已漂移，需统一。

Markdown 渲染逻辑三处重复实现

High

项目已有 useMarkdown.ts，但 NoteCard.vue 手写摘要剥离、NoteEditor.vue 手写预览渲染，与 composable 并存。应统一使用 useMarkdown，既消除 XSS 风险，也减少维护成本。

组件可访问性存在系统性缺陷

High
  • 大量可点击元素使用 <div @click>（NoteCard、CourseCard、AppSidebar 文档行、ChatHistoryPanel 会话行），无 role、tabindex、键盘事件与焦点样式
  • 仅图标按钮缺少 aria-label（AppHeader 汉堡菜单、主题切换、NoteCard/CourseCard 编辑删除）
  • 悬停才显示的操作（opacity-0 group-hover:opacity-100）在触屏设备上无法使用
  • ChatHistoryPanel 手写的删除弹窗无 role="dialog"、焦点陷阱、Esc 关闭，与 el-dialog 模式不一致

组件未完整 TypeScript 化

High

已完成 TS 的组件：CourseCard.vue、NoteCard.vue、ChatHistoryPanel.vue。其余如 NoteEditor.vue（332 行）、TaskPanel.vue（203 行）、TransformDialog.vue、UrlImportDialog.vue 仍为 JS，props 缺少类型与默认值约束。

NoteEditor 组件过大且深度覆盖 Element Plus 样式

Medium

332 行中 200+ 行为 scoped CSS，通过 :deep() 大量覆盖 el-input、el-textarea 内部样式。预览区还自行实现了 Markdown 渲染样式，与 useMarkdown.ts 的输出样式不统一。建议拆分为 NoteEditorToolbar、NoteEditorPreview 子组件。

TaskPanel 自行管理 API 与轮询

Medium

TaskPanel.vue 直接调用 api.get('/tasks') 并维护 refreshTimer，而非使用已有的 taskStore。此外：

  • setInterval 在组件挂载后始终运行，即使无运行中任务也会每 3 秒触发一次空检查
  • el-progress 的 :status success/exception 分支为死代码：它仅在 running || pending 时渲染，不可能到达 completed/failed
  • 任务类型映射、状态文案、状态颜色三个 switch 可合并为一个 Record

TransformDialog 存在可访问性与状态问题

Medium
  • 转换类型按钮使用原生 <button>，未使用 el-button 或 aria-pressed
  • 复制成功提示仅依赖 copied 状态 2 秒重置，无错误处理
  • visible prop 与 localVisible 的同步模式可简化为 computed + emit('update:visible')

line-clamp 重复自定义

Low

Tailwind 3.4 已内置 line-clamp-*，但 CourseCard.vue、NoteCard.vue 仍自定义 scoped CSS 实现，应移除重复代码。

五、视图/页面审查

CourseListView 删除确认按钮绑定错误

Critical

确认删除弹窗中的“删除”按钮绑定的是 confirmDelete 而非 doDelete，导致点击后仅重复打开弹窗，课程永远不会被删除。

<!-- frontend/src/views/CourseListView.vue:119 -->
<el-button type="danger" @click="confirmDelete">删除</el-button>

// 应改为
<el-button type="danger" @click="doDelete">删除</el-button>

视图体积过大，职责混杂

High

以下视图行数过高，建议拆分：

  • ChatView.vue ~450 行：消息气泡、来源卡片、文档选择器、输入区可拆为独立组件
  • CourseDetailView.vue ~450 行：文档标签、笔记标签、笔记 CRUD 与 NotesView 重复
  • QuizView.vue ~410 行：题目卡片、结果统计、错题回顾可拆分
  • NotesView.vue ~376 行：筛选、创建/编辑、草稿逻辑可拆
  • DocumentView.vue ~365 行：列表、阅读器、分页、转换弹窗可拆分

DocumentView 重复实现 Toast

Medium

项目已有 useToastStore，但 DocumentView.vue 使用本地 const toast = ref({ show: false, message: '' }) 自行实现弹窗，造成模式不一致。

ModelConfigView 使用原生表单且错误提示简陋

Medium

该视图使用原生 <select>、<input> 而非 Element Plus 表单组件，样式类字符串大量重复。saveConfig 使用 alert() 提示成功/失败，未接入 toast store。

UploadView 重复校验与缺失错误处理

Medium
  • handleDrop 与 handleFileSelect 均重复 50MB 大小校验
  • deleteDoc 未处理错误也未 toast
  • 模板中直接调用 $refs.fileInput.click()，不符合 Vue 3 组合式风格

QuizView 模式切换按钮视觉失效

High

练习/考试模式切换使用 :class="!examMode ? 'primary' : 'default'"，但 Element Plus 的按钮类型由 type prop 控制，而非 Tailwind 类名字符串。结果两个按钮始终显示默认样式，用户无法识别当前模式。

<!-- QuizView.vue 应改为 -->
<el-button :type="!examMode ? 'primary' : 'default'" @click="examMode = false">练习模式</el-button>
<el-button :type="examMode ? 'primary' : 'default'" @click="examMode = true">考试模式</el-button>

QuizView GSAP 动画目标选择器不匹配

Medium

代码通过 quizListRef.value?.querySelectorAll('.card') 查找题目卡片做入场动画，但模板实际使用 class="el-card p-6"，不存在 .card 元素，导致 stagger 动画从未执行。

Chat Store SSE answer_refined 分支引用未定义变量

High

stores/chat.ts 处理 answer_refined 事件时，使用了一个未定义的 tempMsgId（该分支外未声明同名变量），导致 messages.value.findIndex(m => m.id === tempMsgId) 永远返回 -1，优化后的答案无法替换原流式内容。

AnalysisView 存在未使用变量与死代码

Medium
  • 声明了 const error = ref('') 但模板中从未渲染
  • 导入了 useQuizStore 但从未使用
  • 加载失败时仅 console.error，用户看到空状态却不知原因

ChatView.scrollToReference 未接入模板

Low

ChatView.vue:291 定义了 scrollToReference(sourceIndex)，但模板中来源 badge 的点击事件未绑定该函数，引用跳转功能半实现。

NotesView 草稿 localStorage key 不一致

Medium

自动保存与恢复笔记草稿使用的 localStorage key 存在大小写/命名不一致风险，且 CourseDetailView 也独立实现了类似的 note_draft_${courseId} 草稿逻辑，应抽取为共享 composable。

QuizView 动画选择器脆弱

Low

使用 selector('.mt-4.ml-9.p-4.rounded-xl') 进行 GSAP 动画定位，极度依赖 Tailwind 类名顺序，重构时极易失效。

路由 keep-alive 与 defineOptions 不一致

Low

App.vue 仅对 QuizView、ChatView、AnalysisView 启用 keep-alive，但只有这三者显式声明 defineOptions({ name })。若需扩展 keep-alive，需同步添加 name。

六、分阶段优化方案

Phase 1 · 止血（1 周）

先修复真实影响体验的 Bug 与明显的设计系统断裂。

  • 在 tailwind.config.js 添加 darkMode: 'class'
  • 修复 CourseListView.vue:119 @click="doDelete"
  • 修复 NoteEditor.vue 工具栏/Tab 的 textareaEl 属性访问（.textareaEl → .textarea）
  • 修复 NoteEditor.vue 预览区 XSS 风险，改用 useMarkdown().renderMarkdown
  • 修复 ChatInput.vue 声明并转发 placeholder prop
  • 为 ChatInput、NoteEditor 的 Enter 事件添加 event.isComposing 保护
  • 修复 QuizView 模式切换按钮使用 :type 而非 :class
  • 修复 QuizView GSAP 动画目标选择器（.card → .el-card 或 ref 数组）
  • 修复 stores/chat.ts answer_refined 分支的 tempMsgId 未定义问题
  • 定义 --color-accent-light 暗色值，修复 #010120、bg-blue-50、divide-gray-100 的暗色表现
  • 将品牌渐变统一为 var(--gradient-brand)，并暴露暗色渐变
  • 运行 npx vue-tsc --noEmit 与 npx vitest run 确保基线通过

Phase 2 · 设计系统归一（2 周）

让 token 成为唯一事实来源，减少硬编码与重复。

  • element-plus-theme.css 全部使用 var(--color-*) 等应用 token
  • 移除 global.css 中 .el-card 别名，22 处 class="el-card" 改为 <el-card>
  • Header/Sidebar 布局尺寸使用 CSS 变量 --header-height、--sidebar-width
  • 将 text-[var(--text-muted)] 高频用法沉淀为 .text-muted 等 utility class
  • 统一页面容器、空状态、删除确认等重复布局模式为 Base 组件

Phase 3 · TypeScript 全面覆盖（2 周）

完成剩余视图与组件的类型化，建立组件契约。

  • 所有 .vue 文件迁移至 <script setup lang="ts">
  • props 统一使用 defineProps<{...}>() 与 withDefaults
  • API 错误处理统一使用 AxiosError<ApiError>
  • 补充 types/models.ts 中缺失的视图级类型（如任务、转换）

Phase 4 · 组件与视图拆分（2–3 周）

降低单文件复杂度，提升复用性。

  • ChatView 拆出 ChatMessage.vue、SourceCard.vue、ChatInputBar.vue
  • CourseDetailView 拆出 CourseDocumentList.vue、CourseNoteList.vue
  • QuizView 拆出 QuizQuestion.vue、QuizResult.vue、QuizHistory.vue
  • NotesView 拆出 NoteFilterBar.vue、NoteFormDialog.vue
  • NoteEditor 拆出工具栏与预览区

Phase 5 · 可访问性与性能收尾（1 周）

提升长期可维护性与用户体验。

  • 所有图标按钮补充 aria-label
  • 表单字段补充 <label for> 关联
  • 移除 main.ts 中全局 ElementPlus 注册，仅保留自动导入
  • 修正 tsconfig.node.json 中 vite/vitest 配置文件名
  • 为 GSAP 动画添加 prefers-reduced-motion 保护
  • 建立组件 Storybook/文档或至少 README 说明通用模式
